# Исследование для модуля 12 (SOAP, ШЭП, Kalkan, НУЦ РК)

Дата: 2026-11-25. Метод: веб-поиск (стандартный режим) и проверка поведения XML-DSig на библиотеке `xml-crypto` 6.4.0 в автотесте (`src/engine/xmldsig.test.ts`).

## Что удалось подтвердить источниками

| Утверждение | Источник | Достоверность |
|---|---|---|
| NCALayer — программа для использования подписи НУЦ РК в веб-приложениях; клиентская часть работает как WebSocket-сервер на 127.0.0.1; есть метод `kz.gov.pki.knca.commonUtils.signXmls` для подписи нескольких XML | pki.gov.kz, egov.kz, публикации разработчиков (Habr) | средняя: из результатов поиска, полная документация не читалась |
| Службы OCSP и TSP НУЦ: адреса вида `ocsp.pki.gov.kz`, `tsp.pki.gov.kz`; для CRL фактический адрес указан в самом сертификате | pki.gov.kz (раздел для разработчиков) | средняя |
| NCANode — **сторонний** проект (не продукт НУЦ): подпись и проверка XML, проверка цепочки, OCSP/CRL | Docker Hub (kagiskz/ncanode) | низкая–средняя: описание образа, код не изучался |
| Правила интеграции шлюза «электронного правительства» (ШЭП) существуют как нормативный акт | zakon.uchet.kz | только факт существования документа |

## Что НЕ найдено и потому НЕ описывается в учебнике

- Технические подробности синхронного и асинхронного каналов ШЭП: форматы сообщений, WSDL, обязательные заголовки, тестовый и продуктивный контуры. Поиск нашёл в основном материалы российской СМЭВ, которые **нельзя переносить** на ШЭП.
- API Kalkan Crypt (библиотека), её состав, алгоритмы подписи и форматы (XAdES, CMS) в конкретных интеграциях.
- Требования к цепочке сертификатов и проверке статуса отзыва в конкретных государственных системах.

Эти сведения должен предоставить оператор системы (комплект разработчика, WSDL, регламенты) или официальная документация НУЦ РК. Пока они не получены, уроки по ШЭП и Kalkan содержат только **структуру подготовки и вопросы, которые нужно задать**, но не факты.

## Что проверено локально (общая теория, не специфика РК)

- Подпись XML (XML-DSig) с канонизацией: подмена содержимого ломает подпись; незначимые различия записи (порядок и кавычки атрибутов, пробелы внутри тега) не ломают; значимое изменение текста ломает.
