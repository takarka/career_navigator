## Модуль 1. Node.js: ядро и асинхронная модель

**Цель:** уверенно объяснять, как Node.js работает внутри, и находить блокировки event loop.

**Темы**
- Архитектура Node.js: V8, libuv, thread pool.
- Event loop: фазы, порядок выполнения.
- Microtasks, `process.nextTick`, промисы, `setImmediate`.
- Блокировка event loop: причины и способы устранения.
- Модуль Events: `EventEmitter`, утечки слушателей.
- Streams: виды, `pipeline`, backpressure.
- Worker threads, child process, cluster: когда что применять.
- Обработка ошибок: unhandled rejection, uncaught exception, graceful shutdown.
- Buffer, работа с файлами и сетью.

**Практика**
- **1.1 Порядок выполнения.** Набор фрагментов кода с `setTimeout`, `setImmediate`, промисами и `nextTick`: предсказать вывод, затем проверить.
- **1.2 Блокировка цикла.** Сделать эндпоинт с тяжёлым вычислением, показать деградацию других запросов и вынести вычисление в worker thread.
- **1.3 Потоковая обработка.** Обработать большой файл через streams с `pipeline` и показать, как выглядит backpressure.
- **1.4 Свой EventEmitter-кейс.** Реализовать небольшой модуль на событиях и намеренно воспроизвести утечку слушателей.
- **1.5 Graceful shutdown.** Корректное завершение HTTP-сервера с закрытием соединений и БД по сигналу.

**Результат:** можно за 2–3 минуты объяснить event loop и привести пример блокировки с решением.

## Модуль 3. PostgreSQL

**Цель:** закрыть требование про схему, индексы, транзакции, изоляцию, EXPLAIN ANALYZE и миграции.

**Темы**
- Проектирование схемы: нормализация, ключи, связи, ограничения.
- Индексы: B-tree, составные, partial, covering, GIN; порядок колонок.
- Транзакции, ACID, MVCC.
- Уровни изоляции: Read Committed, Repeatable Read, Serializable; аномалии.
- Блокировки и дедлоки.
- Чтение EXPLAIN ANALYZE: типы сканирования, оценка против факта.
- Пагинация: offset против keyset.
- Миграции: подходы, миграции без простоя.
- Работа из Node.js: пул соединений, ORM или query builder, N+1.

**Практика**
- **3.1 Проектирование схемы.** Спроектировать схему для предметной области (например, заявки и платежи) с ограничениями и индексами.
- **3.2 Разбор плана запроса.** Взять медленный запрос, прочитать EXPLAIN ANALYZE, добавить индекс и сравнить планы.
- **3.3 Аномалии изоляции.** Воспроизвести lost update и non-repeatable read в двух сессиях и устранить их.
- **3.4 Дедлок.** Намеренно получить дедлок и исправить порядок блокировок.
- **3.5 Keyset-пагинация.** Реализовать эндпоинт с пагинацией и сравнить с offset на большом объёме.
- **3.6 Миграции.** Написать серию миграций, включая безопасное добавление колонки и индекса.
- **3.7 N+1.** Найти и устранить N+1 в примере с ORM.

**Результат:** можно объяснить выбор индекса и уровня изоляции на конкретном примере.

- Атомарность: транзакции, Lua-скрипты.
- Распределённая блокировка и её ограничения.
- Персистентность и политики вытеснения.

**Практика**

- **4.2 Инвалидация.** Реализовать сброс кэша при изменении данных.
- **4.3 Защита от stampede.** Показать проблему и решить её блокировкой или jitter в TTL.
- **4.4 Rate limiter.** Реализовать ограничитель запросов на Redis (минимум два алгоритма).
- **4.5 Структуры данных.** Решить задачу с sorted set (например, рейтинг или очередь с задержкой).

**Результат:** можно выбрать структуру и стратегию кэша под задачу и объяснить риски.

**Практика**
- **12.1 SOAP-клиент.** Вызвать публичный SOAP-сервис по WSDL, обработать успешный ответ и Fault.
- **12.2 Свой SOAP-стенд.** Написать простой мок SOAP-сервиса для тестов.
- **12.3 Разбор XML-подписи.** Подписать и проверить XML через NCANode или аналог, разобрать структуру подписи.
- **12.4 Схема асинхронного канала.** Нарисовать, как отправка, ожидание и получение результата ложатся на очередь и таблицу статусов.
- **12.5 Проверка сертификата.** Описать и реализовать шаги проверки цепочки и статуса отзыва.
- **12.6 Рассказ про свой опыт ЭЦП.** Подготовить рассказ про NCALayer и госсистемы и честную формулировку по ШЭП и Kalkan.

**Результат:** понятная база по SOAP и ЭЦП и честный рассказ о том, что уже делал и что освоишь.

## Модуль 13. Capstone: сквозной мини-проект

**Цель:** собрать всё в один проект, по которому можно рассказывать на собеседовании.

**Идея проекта:** сервис приёма заявок с отправкой во «внешнюю госсистему» (мок на SOAP) и подписью документа.

**Состав**
- NestJS, TypeScript, PostgreSQL, Redis.
- REST API и уведомления по WebSocket.
- Асинхронная обработка через брокер: ретраи, DLQ, идемпотентность.
- Outbox для надёжной публикации событий.
- Мок SOAP-сервиса и подпись XML.
- Кэш и rate limiting.
- Docker compose для всего окружения.
- Тесты и нагрузочный прогон.

**Этапы**
- **13.1 Дизайн.** Схема архитектуры, схема БД, контракт API.
- **13.2 Ядро.** CRUD заявок, миграции, валидация.
- **13.3 Асинхронность.** Брокер, outbox, ретраи, DLQ.
- **13.4 Интеграция.** SOAP-мок и подпись.
- **13.5 Надёжность.** Кэш, rate limiting, graceful shutdown.
- **13.6 Качество.** Тесты, нагрузочный тест, README с описанием решений.
- **13.7 Презентация.** Подготовить рассказ о проекте на 3 минуты и на 10 минут.

**Результат:** репозиторий с README и готовая история для технического интервью.

## Модуль 14. Подготовка к собеседованию

**Цель:** превратить знания в уверенные ответы.

**Темы и практика**

- **14.3 Истории STAR.** Минимум 4 истории: оптимизация, инцидент, архитектурное решение, конфликт или ревью.
- **14.4 Слабые места.** Заготовки честных ответов по NestJS, брокерам, ШЭП и Kalkan.
- **14.5 Банк технических вопросов.** Вопросы по каждому модулю: ответить вслух и записать формулировки.
- **14.6 Live coding.** Тренировка типовых задач: async-утилиты, работа со streams, SQL, простой API.
- **14.7 System design.** Две-три тренировки проектирования сервиса на доске с разбором компромиссов.
- **14.8 Зарплатные ожидания.** Диапазон, аргументация и позиция на торге.
- **14.9 Вопросы работодателю.** Список из 8–10 вопросов про стек, процессы, команду, развитие и условия.
- **14.10 Мок-интервью.** Серия тренировок с оценкой: HR, техническое, управленческое. Вопросы по одному, оценка 1–10, разбор ответа.

**Результат:** сформированные ответы, истории и пройденные тренировочные собеседования.
