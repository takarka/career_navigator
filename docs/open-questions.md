# Открытые вопросы

Здесь фиксируется всё, что не подтверждено запуском или официальным источником. В тексте уроков такие места помечаются маркером `[уточнить: что именно]`, а здесь появляется запись с id урока.

| Что | Статус | Что нужно для закрытия |
|---|---|---|
| `labs/docker-compose.yml` | синтаксис и теги образов проверены, запуск не проверен (не было Docker-демона в среде разработки) | выполнить `bash labs/scripts/smoke.sh` на машине с Docker |
| Банк вопросов | сейчас меньше цели в 150 вопросов к релизу | растёт вместе с уроками: блоки `interview` попадают в банк автоматически; статистика — `npm run bank` |
| Модуль 12 (ШЭП, Kalkan, НУЦ РК, NCALayer, NCANode) | исследовательский этап не выполнен; вопросы банка по SOAP и XML-DSig общие, без специфики систем | выполнить исследование по официальным источникам: `docs/research/m12.md` |
| Шаблоны «почему Middle» в уроке m14-l01 | формулировки-заготовки, пользователь редактирует сам | пользователь выбирает и переписывает под свою причину |
| Зарплатные ориентиры | в учебник намеренно не включены | пользователь собирает данные сам (таблица в m14-l04) |
| Урок m01-l03: готовые пулы воркеров (например, piscina) | упомянут без проверки актуальности и API | проверить актуальность по документации библиотеки перед тем, как давать код |
| Урок m01-l04: дженерики EventEmitter в `@types/node` | не проверено, с какой версии типов они поддерживаются | проверить на актуальной версии `@types/node` |
| Урок m01-l05: стабильность Web Streams API в LTS Node | упомянуто без проверки | проверить по документации актуальной LTS-версии |
| Урок m01-l06: пауза перед закрытием сервера в Kubernetes | рекомендуемое значение зависит от инфраструктуры, не проверялось | уточнить у платформенной команды / по документации используемого балансировщика |
| Лаборатории `labs/m08/rabbitmq/*`, `labs/m08/kafka/*` | написаны по документации клиентов (`amqplib` 2.x, `kafkajs` 2.x), синтаксис проверен (`node --check`), но на живых брокерах НЕ запускались | выполнить `bash labs/scripts/run-broker-labs.sh` на машине с Docker или дождаться первого прогона `oracle.yml` |
| Симуляторы RabbitMQ и Kafka (m08-l02, m08-l03) | «модель без оракула на живых брокерах»: логика проверена инвариантами и (для Kafka) сверкой murmur2 и round-robin с `kafkajs` | запустить оракул в CI после первого успешного прогона лабораторий |
| m08-l02: quorum queues против classic, delivery-limit | рекомендации не сверены с актуальной документацией RabbitMQ | сверить с rabbitmq.com/docs |
| m08-l03: retention по умолчанию, «липкий» разделитель, названия стратегий rebalance и новый протокол групп | не сверены с документацией используемой версии Kafka | сверить с kafka.apache.org/documentation |
| Модуль 3: оракул изоляции (`labs/m03/isolation`) | сценарии модели выполняются на реальном PostgreSQL только в CI (`oracle.yml`, job `postgres`); код написан, но НЕ запускался (нет Docker) | запустить job или локально; при расхождении поправить модель `src/engine/isolation.ts` |

| m03-l07: инструменты миграций для Node.js | перечислены без проверки актуальности | выбрать по стеку проекта, сверив с документацией |
